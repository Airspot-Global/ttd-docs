### GET /v3/audience/{audienceId}/{geoForCounts}

<!-- airspot:begin anchor="GET /v3/audience/{audienceId}/{geoForCounts}" -->
> **Airspot note (observed 2026-11-09, sandbox + production; not in TTD's official docs):**
> - Works in sandbox and production. `{geoForCounts}` must be the country **name** (for example `Sweden`, `Norway`). An ISO code such as `SE` returns all counts `null` with `SuccessfullyRetrievedCounts: false`, without an error status.
> - Without the geo segment (`GET /v3/audience/{audienceId}`), the response reports `GeoForCounts: "All Countries"`.
> - Response fields seen: `AdvertiserId`, `AudienceId`, `AudienceName`, `Description`, `IncludedDataGroupIds`, `ExcludedDataGroupIds`, `LastUpdatedAtUTC`, `IsAutoGenerated`, `GeoForCounts`, `UniqueUserCount`, `WebCount`, `InAppCount`, `CtvCount`, `PersonsCount`, `HouseholdCount`, `ActiveIDsCountExpanded`, `SuccessfullyRetrievedCounts`.
> - In production, `HouseholdCount`, `PersonsCount` and `UniqueUserCount` came back identical for a country query. Treat them as an ID count, not as separate household and person counts.
> - `Audience.activeUniques` (GraphQL) and the counts from `GET /v3/audience/{audienceId}` are global, not per country, in production.
> - Risk: the data group variant `GET /v3/datagroup/{dataGroupId}/{geoForCounts}` was retired (HTTP 410 since 2026-08-03). This endpoint may follow.
<!-- airspot:end -->
