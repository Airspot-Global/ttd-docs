# Solimar

Solimar refers to the platform experience before [Kokai](/v3/portal/api/doc/Kokai). We've archived some Solimar-related pages here for reference.

> **TIP**: To get all of the benefits of Kokai, including the upgraded AI, improved relevance, forecasted spending, enhanced decision power, and access to the Sellers and Publishers 500 Plus (SP500+) marketplace, you can use GraphQL to efficiently create, clone, or upgrade your campaigns from Solimar. For details, see [Campaign Creation Workflows](/v3/portal/api/doc/CampaignCreateWorkflows).

The Solimar platform focuses on a goal-centric, data-driven media planning-and-buying experience. To learn more about key differences between Solimar and Kokai, see the [Release Notes](/v3/portal/api/doc/ReleaseNotes2024#may-28-2024) for May 28, 2024.

> **NOTE**: The core functionality for Solimar remains unchanged and accessible. Most pages in the documentation, including those related to using REST API, continue to be relevant to Solimar. For your convenience, this section includes versions of pages created before the introduction of Kokai that are specific to Solimar.

When referring to the API reference guides, note that properties specific to Solimar are labeled `SOLIMAR`, while those exclusive to Kokai are labeled `KOKAI`. For example, in a campaign, the `SeedId` property is exclusive to Kokai and the `AutoAllocatorEnabled` property is specific to Solimar. If a property is not labeled, it applies to both platform experiences.

If you have questions about using Solimar, contact your Technical Account Manager.

### 

How do I upgrade Solimar campaigns to Kokai?

### 

What do the Solimar and Kokai labels or tags mean in the API reference?

Properties specific to Solimar are labeled `SOLIMAR`, while those exclusive to Kokai are labeled `KOKAI`. For example, in a campaign, the `SeedId` property is exclusive to Kokai and the `AutoAllocatorEnabled` property is specific to Solimar. If a property is not labeled, it applies to both platform experiences.

### 

What does it mean when a page appears in both the main documentation and Solimar section?

If you see different versions of a page, one is designed for Kokai users while the other is intended for Solimar users. The page title includes either the word "Kokai" or "Solimar" to help distinguish them.

If a page is not located in the Solimar section, it applies to both platform experiences. For example, the [Bid Lists](/v3/portal/api/doc/BidList) page is relevant to both Kokai and Solimar experiences.
